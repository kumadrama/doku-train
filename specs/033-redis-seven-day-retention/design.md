# Spec 033：S3 / Redis 联合七天清理

Source: 2026-11-02 用户最终决策，两侧均保留 7 天；Spec 009 / 010 及现有 publication.py、redis_distribution.py。

状态：简化设计已确认；取代本 Spec 先前独立 Redis 生命周期草案。本地实施中，未部署。

## 变更前状态

S3-only Registry.cleanup 与 Redis 联合 Distribution.cleanup 均按 created_at 保护 30 天。Redis 联合 drain 会撤销两侧日期引用，联合 delete 删除登记的 Redis 键、S3 模型文件及分发 descriptor。

## 已确认设计（本地已实施，尚未部署）

- 两个清理入口的保留年龄统一改为 7 天；精确边界沿用原语义：年龄不超过 7 天仍保护，超过 7 天才有资格进入排空。
- 沿用原有联合生命周期、持久操作、目录 CAS、引用检查和恢复行为，不增加 Redis 独立生命周期或新消费者协议。
- current、生产者、替换保护、pin 和 24 小时排空保护不变；删除范围仍为登记的模型制品，不包含上游样本和共享冻结输入。
- 同步更新 Spec 009 / 010 与 architecture 中当前有效保留规则及测试；历史证据保留历史语义。
- 以合成数据验证 7 天前、恰好 7 天、超过 7 天、24 小时排空、current/pin 保护、联合删除与中断恢复；执行 make check。

## 生产恢复

本地代码验收后另行记录部署和生产清理验证。处理现有 pending 操作前确认旧写入者和自动重试已停止；先 dry-run，再按原协议排空和删除，不自动清锁或跳过保护期。删除后恢复已有成功训练版本的分发，不重新生成样本。

## 2026-11-05 规划冲突重试

Source: 生产清理异常与用户确认的修复方案。
