状态：2026-10-20 已实现并部署，单个真实 DNN train/test/归档与指标数据验收通过；浏览器视觉验收及 15 并发未完成。

本次确认取代旧草案中的环境、CPU/GPU、实验方式和中断恢复待定项。

## 1. 目标与阶段

最终目标包括：缩短实验耗时、释放本地机器、统一运行管理，以及并行实验。

- 第一阶段：将 DNN / DeepFM 实验训练迁至 SageMaker Training Job，使用单机 CPU。
  本地编辑实验 YAML、命令提交多个独立任务，使用 AWS 自带网页查看任务与日志，
  展示各任务 AUC 与 loss 曲线，由用户判断实验效果。
- 第二阶段：将用户选定方案的每日训练与评估接入 SageMaker，并衔接模型交付与现有线上实验。
  每日触发、导出与发布合同须后续单独确认；线上推理与 A/B 实验继续在现有系统进行。
- 第一阶段不迁移现有树模型每日链路，不部署在线 Endpoint，不自动发布实验模型。

## 2. 已确认需求

### R1：保留仓库与配置体验

- 复用 doku-train 现有模型、训练和评估用例，不复制算法实现，不引入新的训练框架。
- 实验 YAML 是数据日期、切分、特征、任务、网络、超参数、CPU 线程与内存预算的权威。
- 云端运行配置与实验 YAML 分开，承载环境、region、镜像、执行角色、网络、实例、磁盘、
  超时和实验输出位置。平台不得静默改写训练语义。
- 同批超参数实验由用户在 YAML 保持相同数据与切分；不建设强制批次管理或自动搜索系统。
- 提交后本地修改 YAML 或源码，不影响已提交任务。每个 Run 冻结配置、数据合同与源码身份。

### R2：资源与执行

- 使用 PROD 账号的独立实验输出与权限范围；训练读取指定数据，写入专用实验路径。
- 规划实例为 ml.m5.2xlarge（8 vCPU / 32 GiB），每任务一台，支持至少 15 个独立任务并行。
- 首期采用按需实例；失败修正后完整重跑，不提供云端中断续训、Spot 或多机训练。
- 完整任务一小时以内是待实测性能目标，包含训练准备、训练、评估与产物处理；
  不将一小时直接设置为强杀阈值。另记录提交到完成的总等待时间和 AWS 实际计费用量。
- 本地 CPU 验证路径继续保留；不自动增加 YAML 中的 CPU 线程数。

### R3：比较与产物

- 按 YAML 声明的任务展示各任务 AUC，注明 validation/test、样本统计和不可计算原因。
- 不新增跨实验加权排名或自动选优；现有单 Run 内 YAML 声明的 checkpoint 选择逻辑保持不变。
- 保留 checkpoint.pt、metrics.json、fitted-feature-state/state.json、lineage.json，
  以及冻结输入、resolved config、独立 test 结果和运行身份。
- 输出 run-scoped、create-only；训练失败或上传不完整不能被视为成功实验。
- 保存训练结果不等于发布：首期不得更新 active/发布清单、分发线上 Redis 或切换 A/B 模型。

### R4：操作界面

- 使用本地命令提交、查询任务及汇总结果，返回 AWS 任务链接。
- 首期不创建或使用 Studio Domain；本地提交，在 SageMaker 控制台 / CloudWatch 网页
  查看任务和日志；AUC/loss 曲线必须支持 step 横轴。CloudWatch 时间曲线不能单独满足此要求，
  采用本地 TensorBoard 网页；云端指标同步至 S3，本地同步查看，不开发自定义训练平台网页。
- 指标必须在训练过程中持续输出与采集，不能只在结束后保存 metrics.json。
  明确区分 train/validation/test 和任务名；不可计算的 AUC 不伪造为 0。
- 后期可接入 Studio，复用现有镜像、提交接口、YAML 和 S3 产物；若接入实验跟踪工具，
  历史结果需显式导入，不承诺自动出现在新界面。
- AUC 汇总必须可用；不假设 AWS 会自动读取 metrics.json 生成跨任务对比。
  第一阶段不以额外常驻实验跟踪服务为前置条件。

## 5. 验收要求

- 合成数据覆盖配置冻结、入口调用、train/test、非零失败退出、产物完整性及重复输出拒绝。
- 同一冻结输入与配置可追踪复现；不承诺跨 CPU 架构逐位一致。
- 指标不可计算不阻断其他指标与可用训练产物保存；输入/执行错误必须失败。
- 记录准备、读取、拟合、编码、训练、评估和归档耗时、吞吐、峰值内存及运行资源。
- 云端验收经另行授权后执行：先单任务冷启动，核查完整产物与费用，再验证 15 并发；
  不能以配额查询替代并发实测。
- 实现阶段运行 make check 和平台适配合同测试；文档阶段验证见 verification.md。
