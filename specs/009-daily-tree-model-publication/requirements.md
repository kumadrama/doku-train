# Spec 009：树模型每日训练与发布需求

状态：需求已确认，2026-10-13 用户授权实施；不部署、不执行云端操作。

Source: 2026-10-13 用户逐轮确认 Q1–Q27，最终要求新增 requirements 与 design。
同日后续确认取代早期备选：至少三个数据日；允许同名合同变化正常发布；历史产物保留 30 天。
设计见 [design.md](design.md)。

## 1. 目标与边界

- R01：本仓负责 CPU XGBoost 每日训练、独立测试评估、checkpoint、推理导出、S3 上传、
  发布清单更新、回滚和定时清理入口。首版不依赖 Spec 008 的 SageMaker DNN 平台。
- R02：直接上游是 doku-offline/fyp-rank-samples 的训练投影。上游成功发布后由 doku-iac
  触发本仓单次流水线；run.py 执行一次退出，不维护常驻计时循环。
- R03：基础设施、角色、桶、调度与环境装配归 doku-iac；告警接入归 doku-monitoring；
  调用方特征编码、版本传递、predictor-svc 加载与 RPC 实现归 doku-mono。
- R04：只通过版本化数据/制品合同协作，不 import 相邻仓库实现，不复制 Finder 私有代码。
  默认 CPU hist、单机单训练进程，资源显式配置，无生产默认值。

## 2. 配置、身份与版本

- R05：model_type 与 model_name 均由 YAML 显式指定。现有用于插件选择的 model_name
  改名为 model_type；新增 model_name 是用户自定义模型身份，不根据配置内容自动命名。
- R06：不同配置可使用同一 model_name，包括输入输出合同变化；无需改名，也不因合同
  不兼容阻止正常发布。记录版本化合同，调用方报错后的适配由 mono 负责。
- R07：每日数据、配置或源码变化可生成独立 model_version。产物目录为
  model_name/日期/model_version/...，日期为 test 数据日期，创建时间另记。
  “覆盖同名”指更新发布清单，不物理覆盖已有版本文件。
- R08：相同冻结输入、有效配置、源码及执行环境不重复训练；提供显式重跑能力。
  同名流水线串行，不允许旧任务晚完成后将日更清单退回；不同名称可并行。

## 3. 数据窗口与训练

- R09：从冻结 Manifest 选择最新可用数据日为 test，前一个可用数据日为 validation；
  在 validation 之前 30 个自然日内取所有可用日期训练，不向更早日期补足 30 个有数据日。
  30 天是本次配置值，不是框架固定限制；日界线遵循上游 UTC 合同。
- R10：train、validation、test 各至少一天有效数据，总计至少三个不同自然日。
  数据不足时不启动本轮训练/发布，保留旧版本；不采用一天内拆分或两天降级方案。
  不猜测缺日是空日还是产出失败，缺日可跳过；已存在分片的合同、摘要、行数等错误仍失败。
- R11：实际日期、输入与合同原文及摘要必须冻结。训练只消费精确不可变 Manifest；
  评估、导出重跑不重新解析日更数据。词表与统计只在 train 拟合，无 test 泄漏或强制 refit。
- R12：validation 用于早停与选轮数，指标由 YAML 独立声明；test 仅在 checkpoint 固定后
  计算发布指标。任务集合、标签、mask、目标及超参数由配置声明，不固定为四个模型。
  任一必需任务无训练标签，整次训练失败，不混合新旧任务 checkpoint 发布。

## 4. 评估与发布门禁

- R13：评估独立加载成功 checkpoint 和冻结 feature state，可重跑，不重训、不改 checkpoint。
  训练期间 validation 早停仍在训练过程内。CheckpointAgent 管持久化，不另设保存脚本。
- R14：各必需任务的发布指标及阈值在 YAML 声明，本次分类 AUC 与 regression_auc 下限
  均为 0.60；等于阈值通过，任一低于阈值或不可计算则整包不发布。没有相对下降门禁。
- R15：regression_auc 在整个 test 集的有效标签样本间计算：真实标签相等的对排除；
  预测同序计 1、预测相等计 0.5、逆序计 0，除以可比较对数。指标越高越好，
  不是逆序比例，也不是标准分类 ROC AUC。无可比较对记录 null 和原因。
- R16：误差等其他指标照常记录，不新增未配置门禁。指标拒绝不撤销已成功的训练，
  保留 checkpoint、评估报告、样本统计及发布拒绝原因；数据/执行错误如实失败。

## 5. 导出、发布与消费合同

- R17：export_model.py 从成功训练产物导出原生 XGBoost 模型文件、任务及输出语义、
  特征顺序/类型、fitted feature state、model_name/model_version、文件摘要和来源信息。
  checkpoint.xgb.zip 仍是训练内部格式，不充当在线加载合同；不引入 ONNX。
- R18：完整性校验、重新加载及导出前后预测一致性验证通过后，才允许提交发布清单。
  同一个版本内所有任务、编码状态和元数据一致；任何失败不更新原发布清单。
- R19：本仓发布按 model_name + test 日期解析的“最新成功发布版本”清单，且维护当前发布
  版本；不能通过列目录取最新文件。业务调用方可不手写 model_version，但公共组件须
  每请求只解析一次，以同版本编码特征，并自动将该版本传给 predictor。
  predictor 不可静默替换请求版本；上述消费实现属于 mono。
- R20：首次发布完整校验后再接流量。更新失败继续用旧版本；没有可用版本时消费者明确
  返回不可用，由调用方兜底。支持显式回滚到仍保留的历史成功版本，不重训。

## 6. 保留与清理

- R21：本仓提供清理入口，由 iac 每天触发。按创建时间清理超过 30 天的训练产物、
  导出产物与失败残留；当前发布版本始终保留，刚被替换版本至少再保留 24 小时。
- R22：保护仍在执行/使用的产物；删除前重查发布清单，避免发布、回滚、清理竞争。
  24 小时过渡期需要消费者协调，不声称仅凭 S3 目录即可知道服务中的所有引用。
  已清理版本不再支持回滚或按日期解析为可用版本，历史清单不得留下有效的悬空引用。
