在现有 Grafana 看板中展示每日训练实际选中 checkpoint 的主任务 AUC / MSE；不同模型自动登记并出现，无需逐模型修改看板、日志查询、采集权限或监控部署配置。

当前状态：

- TF 训练已有配置驱动选模，`training/selection.json` 是最终选中 epoch 的权威记录。
- `training/epoch-metrics/NNNN.json` 已保存每轮完整 validation 指标；不需要再次评估或训练。
- Spec 013 看板使用模型 YAML 静态生成 Row，不能自动发现新增模型，当前标题为 Training Test AUC Prod。
- 当前日更配置没有稳定业务 `model_name`；SageMaker 训练任务名逐次变化，不能作为跨日模型分组键。
- Spec 028 已完成 28+1 日更、Endpoint 更新、回滚/恢复与自动触发验收；它的实际最终状态以 Spec 028 verification.md 为准。

## 2. 已确认需求

### R1 模型身份

1. 日更使用的模型配置增加 `model_name`，当前配方采用 `tf_rerank_ln_lr001`。
2. 不同模型配方使用不同 model_name；同一配方每天改变数据日期、Manifest、运行编号，不改变 model_name。
3. model_name、单次训练任务名、具体模型版本分别保存，禁止混用；看板按 model_name 归组，提供真实 SageMaker 训练任务链接。
4. model_name 由配置贯穿训练产物、发布记录与监控，不另建人工维护的监控模型名单。
5. 当前 Endpoint 名保持 `doku-prod-tf-rerank`；model_name 与部署目标通过显式环境绑定关联，不重命名现有资源。

### R2 复用选模与指标

1. 不新增第二套选模算法，不重排 epoch，不为监控重新计算 AUC/MSE。
2. 读取 selection.json 的 epoch，再读取对应 epoch-metrics 记录；四任务必须来自同一选中 epoch。
3. 指标选择复用任务配置的 func；当前 completion、fast_swipe、immersive_click 使用 auc，watch_seconds 使用 mse。
4. 不把训练/选模 loss 误称为 MSE。若任务同类型指标存在歧义，应要求显式选择，不能静默取第一个。
5. 当前四个主任务取自既有发布输出合同；辅助任务不自动加入默认四图，不复制另一份主任务名单。
6. 看板统一标为 Test AUC / Test MSE，这是用户要求的显示名称。底层保留真实 evaluation_split=validation；不增加 test 阶段或第 30 天数据。
7. 指标不可计算时展示空值和原因，不补零、不回退到旧 run 的非空值。

### R3 日期、重跑与发布状态

1. 按数据截止日归档趋势点，而非日志到达日或投递日。
2. 同一模型、同一截止日多个成功训练 run，选择最后一次完成训练的整条观察；四任务不能分别取 max/min/avg。
3. 训练成功但部署失败，训练指标仍可见，明确显示发布状态。
4. 当前 Endpoint 实际在线版本单独展示；不能将“最新完成训练”当成“当前在线”。
5. 回滚不修改历史评估值；补报使用原时间、原身份，不能覆盖更晚完成的训练结果。

### R4 自动发现与兼容范围

1. 新模型使用统一配置、训练产物和平台发布入口，即可自动登记到模型目录并出现在原看板中。
2. 本次只接入 recommend_tf，支持统一合同下的新 TF 模型；不新增 recommend/train 的树适配，不修改树训练代码。
3. 原树模型历史 Row 暂时保留，不迁移或重新投递树历史日志；其现有日期与查询口径保持不变。
4. 不把监控合同限制为一模型一 Endpoint。当前部署能力继续使用独立固定 Endpoint，多模型共享 Endpoint 另行设计。
5. 不因本次监控让尚未具备推理导出/发布能力的模型获得上线能力；例如 cangen 训练能力不等于已实现其线上发布。

### R5 投递与恢复

1. 监控故障不改变成功训练/发布结论，不新增模型质量门禁。
2. 监控源文件和事件持久保存；采集、投递和看板同步失败可独立恢复、告警，不要求重新训练。
3. 重试使用稳定事件 ID；允许日志至少一次投递，但看板结果必须去重且抗乱序。
4. 保留来源摘要与状态，能追溯指标属于哪个 run、epoch、训练配置和数据集。
5. 训练失败或无法选模时记录状态，不伪造一个“最佳 epoch”或有效指标点。

### R6 回填

1. 平台层提供显式历史 run / 日期范围回填入口，复用正常读取、标准化与投递逻辑。
2. 首次接入补入已有成功日更结果；后续补偿漏报。
3. 不自动扫描全部离线实验，不重新训练、不重新评估、不改写已有封存 run。
4. 旧产物缺少新字段时，使用可审核的显式绑定补充模型身份；不能从训练任务摘要猜模型名，不能改写旧 lineage/config。
5. 历史证据不足时明确列出无法回填的原因，禁止伪造指标、时间或发布成功状态。

## 4. 验收要求

- 所选指标严格对应 selection.json；覆盖加权 loss 选模和 early_stop 两种现有路径。
- 模拟新增第二个模型，提交统一事件后自动出现新的 Row，无模型专属看板/IAM改动。
- 同截止日重复、乱序、最新 null、不同 run 完成时间的回放结果正确且四任务同源。
- 训练成功/发布失败、回滚/恢复等状态正确；当前在线记录与真实 Endpoint 版本一致。
- 监控故障不改变训练/发布成功状态；恢复后无重复业务数据点，无旧状态覆盖新状态。
- 对既有 28+1 成功 run 回填，数值匹配保存的选中 epoch，旧 run 全部文件摘要不变。
- 同一 Grafana UID 保留原树历史 Row；新 TF AUC/MSE 轴、空值、时间和状态通过实际查询验收。
- 离线实验入口不增加网络投递，不改变训练、评估、选模、test 日期或结果语义。
